# ながら聴き（nagara-kiki）デプロイ手順

```
nagara-kiki/
├── index.html      … GitHub Pages
├── style.css       … GitHub Pages
├── config.js       … GitHub Pages（GAS_URL をここに書く）
├── app.js          … GitHub Pages
└── gas/Code.gs     … Google Apps Script に貼り付け（GitHubに置くのは任意）
```

## 1. スプレッドシートと GAS

1. Googleスプレッドシートを新規作成（名前例：`nagara-kiki-db`）
2. メニュー「拡張機能」→「Apps Script」を開く
3. `コード.gs` の中身を全部消して `gas/Code.gs` を貼り付け、保存
4. 関数選択で `setup` を選び「実行」
   - 初回は権限の承認が出る →「詳細」→「安全ではないページに移動」→ 許可
   - Users / Sessions / Favorites / History / Playlists / PlaylistItems / Contacts のシートが作られ、PEPPER が自動登録される
   - 既存のシートには、足りない列（kind・url・share_on など）が右端に自動で追加される（データはそのまま）
5. 左の歯車「プロジェクトの設定」→「スクリプト プロパティ」に追加

| プロパティ | 必須 | 内容 |
|---|---|---|
| `GEMINI_API_KEY` | 必須 | Google AI Studio で発行したキー |
| `YOUTUBE_API_KEY` | 推奨 | YouTube Data API v3 のキー（下記） |
| `APP_URL` | 任意 | `https://kenken6291.github.io/nagara-kiki/`（メールに記載） |
| `GEMINI_MODEL` | 任意 | 既定 `gemini-2.5-flash` |
| `GEMINI_TTS_MODEL` | 任意 | DJ紹介の音声合成。既定 `gemini-2.5-flash-preview-tts` |
| `GEMINI_TTS_VOICE` | 任意 | DJ紹介の声。既定 `Aoede`（`Kore`・`Puck` など） |
| `PEPPER` | 自動 | **変更しない**（変えると全員ログイン不可） |

### YouTube Data API キー（AI選曲を実際の動画にするため）
Geminiは実在の動画IDを正確に知らないため、GAS側で「曲名 アーティスト」をYouTube検索して動画IDに変換しています。

1. Google Cloud Console → プロジェクト作成（既存でも可）
2. 「APIとサービス」→「ライブラリ」→ **YouTube Data API v3** を有効化
3. 「認証情報」→「APIキーを作成」→ キーを `YOUTUBE_API_KEY` に登録
   - 制限は「APIの制限：YouTube Data API v3」だけ付ける（GASから呼ぶのでリファラー制限は付けない）

無料枠は1日10,000ユニット、検索1回100ユニット。AI選曲1回で最大8検索＝800ユニットなので、**1日およそ12回分**（同じ検索語は6時間キャッシュされるので実際はもう少し多い）。
未設定でも動作し、その場合は各曲に「YouTubeで探す」リンクが出ます。

## 2. ウェブアプリとしてデプロイ

1. 右上「デプロイ」→「新しいデプロイ」→ 種類「ウェブアプリ」
2. 次のユーザーとして実行：**自分**
3. アクセスできるユーザー：**全員**
4. 「デプロイ」→ 表示された **ウェブアプリURL（…/exec）** をコピー
5. ブラウザでそのURLを開き `{"ok":true,...}` が出ればOK

> ⚠ Code.gs を修正したら「デプロイを管理」→ 鉛筆 → バージョン「**新バージョン**」→ デプロイ。
> これをしないと修正が反映されません（URLは変わりません）。
> 「新しいデプロイ」でURLが変わった場合は `config.js` だけ書き換えてアップロードしてください。

## 3. GitHub Pages

1. GitHubで `nagara-kiki` リポジトリを作成（Public）
2. `config.js` の `GAS_URL` を手順2のURLに書き換え
3. `index.html` / `style.css` / `config.js` / `app.js`（と任意で `gas/`）をアップロード
4. Settings → Pages → Branch: `main` / `/(root)` → Save
5. 数分後 `https://kenken6291.github.io/nagara-kiki/` で公開

## 4. CORS・通信の注意点

- フロントは `Content-Type: text/plain` でPOSTしています。`application/json` にするとプリフライト（OPTIONS）が発生し、GASは応答できずに失敗します。
- GASの `/exec` は `script.googleusercontent.com` へ **302リダイレクト**して結果を返します。`fetch` は `redirect: 'follow'`（既定）で自動追従するので追加対応は不要です。
- 「サーバーの応答を読み取れませんでした」と出る場合は、アクセス権が「全員」になっていない（Googleのログイン画面HTMLが返っている）ことがほとんどです。

## 5. 動作確認の順番

1. 新規登録 → メールで仮パスワード受信
2. 仮パスワードでログイン → 新パスワード設定画面が出る
3. お気に入りにYouTubeのURLを追加 → 再生 → 曲の終わりで次へ進む
4. AI選曲 → 「この選曲で再生」「まとめて追加」→「DJの紹介を聴く」／「話す」で音声入力
5. Amazon Music のURLを追加 → 再生 → 「Amazon Musicで開く」→「次へ」
6. 別アカウントを用意 → 「共有」で公開相手に追加 → プレイリストを公開 → 「LINEで送る」のリンクを別アカウントで開く
7. 公開をオフにして、相手側から見えなくなることを確認
8. ログアウト → 「パスワードを忘れた方」→ 6桁コードで再設定

## 6. 仕様メモ

- パスワード：SHA-256 ×300回＋ソルト＋ペッパー。英字＋数字8文字以上
- ログイン5回失敗で15分ロック（再設定コードの入力ミスも同様）
- セッション：14日間。Sessionsシートに保存し、CacheServiceで高速化
- 仮パスワード有効期限24時間、再設定コード30分
- AI選曲：1ユーザー6時間あたり15回まで
- 履歴シートは5,000行を超えると古い1,000行を自動削除
- 埋め込み禁止の動画は追加時にはじき、再生時にエラーが出たら自動で次の曲へ

## 7. マイプレイリスト（1人30個まで）

- Code.gs に統合済み。`Playlists` / `PlaylistItems` シートは初回アクセス時に自動作成（`setup()` を再実行しても可）
- 上限：1人30個、1プレイリスト200曲、名前30文字（Code.gs 冒頭の `MY_PLAYLISTS_MAX` などで変更可）
- 追加方法：動画URL、YouTubeプレイリストURL（`YOUTUBE_API_KEY` 必要）、お気に入りから選択、お気に入り・AI選曲・履歴・再生中の曲の「＋」
- お気に入りとは独立（お気に入りから消してもプレイリストには残る）
- 一覧の表示順は「並べ替え」→ ◀ 前へ / 後へ ▶ → 「完了」で自由に変更できる（`Playlists` シートの `sort_order` 列に保存。既存シートには列が自動追加される）

## 8. Amazon Music

- お気に入り・プレイリストの欄に Amazon Music の URL（曲・アルバム・プレイリスト・アーティスト等）を貼ると登録できる。`amzn.to` などの短縮URLもGAS側で展開する
- 曲名は Amazon のページから自動取得を試みるが、取れないことが多いので追加時に入力欄を出している（空欄可）
- 「共有」→「埋め込み」のコード（`<iframe …music.amazon…/embed/…>`）を貼ると、画面内に Amazon の埋め込みプレイヤーを表示する
- **Amazon Music には曲の終わりを知らせる仕組みがないため、自動で次の曲へは進まない。**「Amazon Musicで開く」で聴き、終わったら「次へ」
- シートの `video_id` 列には `am_種類_ID`（例 `am_a_B0XXXXXXX`）を保存。`kind` 列が `amazon`

## 9. 家族・友人だけに公開（共有）

- 「共有」タブで、公開相手（登録会員のメールアドレス・呼び名・区分〔家族／友人／その他〕）を登録（1人50人まで）
- プレイリストごとに公開スイッチ（既定は非公開）と公開相手を設定。一覧のスイッチでその場で切り替え
- 公開相手から削除すると、その人に公開していたプレイリストからも自動で外れる（誰もいなくなれば非公開に戻る）
- 「LINEで送る」：`https://line.me/R/share?text=` でリンク付きの案内文を送る。ほかに「ほかのアプリで送る（Web Share）」「メール」「コピー」
- リンクは `https://kenken6291.github.io/nagara-kiki/?share=プレイリストID`。開くとログイン後に該当プレイリストを表示。公開相手でない人には見えない
- 相手にはニックネームだけが表示され、メールアドレスは表示されない
- シート：`Contacts`（owner_email, member_email, label, relation）、`Playlists` の `share_on` / `share_to`（JSON配列）

## 10. 会員登録時の同意

- 「注意書き」「免責事項」「自己責任」「当事者間での問題解決」の4項目すべてにチェックしないと登録できない（サーバー側でも確認）
- `Users` シートに `agreed_at` / `terms_version` を保存
- 文面を変えたら `app.js` と `Code.gs` の `TERMS_VERSION` を両方上げる → 既存会員は次回ログイン時に同意画面が出る
- 文面は `app.js` 冒頭の `AGREE_ITEMS` / `TERMS_EXTRA` で編集

## 11. 音声入力・DJ紹介・使い方・バージョン

- AI選曲の「話す」：Web Speech API。無音で認識が止まっても「止める」を押すまで自動で再開（60秒話さないか5分で自動終了）
- 「DJの紹介を聴く」：Gemini TTS に**読み上げ本文だけ**を送る（「〜で読み上げてください」などの指示文を入れると、それまで読まれてしまうため）。AIの返す文と送る直前の両方で、冒頭の指示文・見出し・ト書きを除去。失敗時は端末の読み上げで代用。1人6時間30回まで
- 画面右上「使い方」、フッターに「注意事項・免責事項」「使い方」
- 画面下に `ver 1.9.0（日付 更新）／サーバー 1.9.0`。`config.js` の `APP_VERSION` と `Code.gs` の `SERVER_VERSION` が違うと赤字（GASのデプロイ忘れの目印）

## 12. Excel 書き出し・取り込み

- 「プレイリスト」一覧の下の「Excel」：すべて書き出す／取り込む／ひな形をダウンロード。各プレイリスト画面・公開されたプレイリスト画面にも「Excelに書き出す」
- ブラウザ内で処理（SheetJS 0.18.5 を cdnjs からボタンを押したときだけ読み込む）。GAS側の変更は不要
- 書き出し形式：シート「プレイリスト」に `プレイリスト名 / 順番 / 種類 / 曲名 / チャンネル・アーティスト / URL`、シート「使い方」に説明と記入例
- 取り込み：.xlsx / .xls / .csv。「URL」列（無ければURLらしいセル）を読み、「プレイリスト名」ごとにまとめる。名前が空欄の行は直前と同じプレイリスト、名前列が無ければファイル名を使う
- 同じ名前のプレイリストがあれば後ろに追加、無ければ新規作成（30個・200曲の上限、重複はサーバー側で除外）。取り込む前に確認画面でプレイリストを選べる
- サーバーへは最大100曲ずつ（曲名なしのYouTubeは25曲、Amazonは5件ずつ）送る

## 13. できないこと（YouTube・Amazon側の制約）

- Amazon Music の曲は自動で次へ進みません（上記）。再生には Amazon Music のログインが必要な場合があります。
- **スマホで画面を消す／別アプリに切り替えると再生が止まります。** 埋め込みプレイヤーのバックグラウンド再生はYouTubeが許可していません（YouTube Premium の公式アプリのみ）。画面をつけたまま、このタブを開いておけば連続再生されます。
- プレイリストURLは最大200曲までまとめて追加できます（`YOUTUBE_API_KEY` が必要）。
- YouTubeが自動で作る「ミックス」（`list=RD…`、ただし YouTube Music の `RDCLAK…` は可）、「後で見る」「高く評価した動画」などの個人用リスト、非公開プレイリストは読み込めません。
